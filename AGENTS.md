# AGENTS.md — nvim-config

Canonical repo-wide instructions for coding agents (opencode-first).
This file is the single source of truth — no `CLAUDE.md` / `GROK.md`
pointers, no adapter directories. opencode reads this file natively.

You are a senior LazyVim / lazy.nvim specialist. Act surgically:
minimal diff, single concern per change, no drive-by refactors.

## Repo map

- `init.lua` — bootstrap only: `require('config.lazy')`. Do not expand.
- `lua/config/lazy.lua` — lazy.nvim setup. `spec` is
  `LazyVim/LazyVim` + `{ import = 'plugins' }`.
  `defaults.lazy = false`, `version = false`. Leader keys before load.
- `lua/config/options.lua` — overrides only, inherits LazyVim defaults.
  Cross-platform guards (`win32` pwsh block, `SSH_TTY`/OSC52 clipboard)
  must stay.
- `lua/config/keymaps.lua`, `lua/config/autocmds.lua` — stock LazyVim
  passthrough today. New global maps/autocmds go here; plugin-local
  maps stay in that plugin's `keys` spec.
- `lua/plugins/*.lua` — one plugin (or tight group + its `which-key`
  spec) per file. Exemplars: `lua/plugins/cmake.lua` (lazy `ft`/`cmd`/
  `keys`, `opts` table), `lua/plugins/opencode.lua` (`keys`-driven
  spec, server via `snacks.terminal`, `<leader>o` group).
- `lazyvim.json` — extras source of truth, managed via `:LazyExtras`.
  Never hand-duplicate an extra as a manual spec.
- `lazy-lock.json` — generated by `:Lazy update`. Never hand-edit.
- `stylua.toml`, `.luarc.json`, `.neoconf.json` — formatter + LuaLS.
  Obey them; do not reformat unrelated files to satisfy them.
- `docs/`, `Dockerfile`, `.github/workflows/` — reference, reproducible
  image, CI (`stylua --check`).

## Surgical rules

1. Read the target file plus the LazyVim upstream default before
   editing. Evidence before synthesis.
2. Smallest diff that fixes the issue. Preserve style, comments,
   annotations around the change.
3. One file per plugin. Never merge unrelated plugins into one spec.
4. Prefer `opts = {}` over `config = function() ... end`. `config`
   only for runtime work (keymaps needing `require`, autocmds,
   `vim.g.<plugin>_opts` globals like opencode).
5. Lazy-load aggressively: `ft`, `cmd`, `keys`, `event`. Declare
   `dependencies` explicitly. Never set a global `lazy = true`
   flip to fix one plugin.
6. Keymaps: `keys = { { '<leader>xx', ..., desc = '...' } }`
   (`LazyKeysSpec`), every map has `desc`. Register `<leader>`
   groups via `which-key.nvim`
   `spec = { { '<leader>xx', group = '...' } }`. Check for prefix
   collisions first (`<leader>a` Android, `<leader>ck` CMake,
   `<leader>o` Opencode, `<leader>s` search, `<leader>R` remote).
7. Options: deltas only in `lua/config/options.lua`. Reference the
   upstream default in a comment when overriding.
8. No `vim.cmd` where `vim.opt` / `vim.g` / `vim.keymap.set`
   suffices. No hardcoded absolute paths; use `vim.fn.stdpath`,
   `vim.uv.cwd()`. No synchronous shell-outs at startup.

## Lua style

Comments are rationed: one line, say why never what. Two or three
lines only when the block opens with `-- WHY:`, once per change.
`-- Plugin: <url>` / `-- Health: <cmd>` headers on plugin files are
free. Never add what-comments (`-- set foo to bar`), never remove a
still-correct comment to satisfy the budget.

- Runtime is LuaJIT (`syntax = "All"` but code must run on LuaJIT).
  Only global is `vim`.
- Annotate: `---@type LazyPluginSpec[]`, `---@type LazyKeysSpec[]`,
  `---@type opencode.Opts`, `---@type conform.setupOpts`, etc.
- StyLua, enforced in CI: `column_width = 80`,
  `indent_type = "Spaces"`, `indent_width = 4`,
  `quote_style = "AutoPreferSingle"`,
  `call_parentheses = "Always"`,
  `collapse_simple_statement = "Never"`, `[sort_requires]` on.
  Single quotes, always parens, sorted contiguous `require()`s.

## Text file format

- LF-only everywhere (`fileformat=unix`, `bomb=false`,
  `modeline=false`). Never introduce CRLF or BOM; normalize back if
  a tool does. Exception: files that already use another convention
  keep it.
- `readme.md` never duplicates keymaps — the code is the source of
  truth. Update `docs/` only when a workflow changes.

## Commits

- Subject: one concise plain-language line, ~50–60 chars, matching
  recent `git log` style. That is usually the entire message; add a
  one-or-two-line body only when the subject cannot carry the what
  (never the technical how).
- Never add `Co-Authored-By:`, tool/assistant attribution, or run
  markers. Never commit the disposable opencode overlay or external
  task artifacts.

## Verification (run before done)

```bash
stylua --check .
nvim --headless -V1 -c 'checkhealth' -c 'qa'
nvim --headless "+Lazy! sync" +qa
:checkhealth opencode   # after touching lua/plugins/opencode.lua
```

Docker parity: `ghcr.io/e-gleba/nvim-config/nvim-ci:latest` runs
`stylua --check`. If behavior is in doubt, re-run headless in the
container before concluding the config is broken.

## Troubleshooting

- `stylua` missing locally: use the CI image or install pinned
  `STYLUA_VERSION` from `Dockerfile`. Do not reformat with another
  formatter.
- `:LazyExtra` vs manual spec conflict: the extra wins — delete the
  manual duplicate, keep `lazyvim.json` as truth.
- Lockfile churn after `:Lazy update`: commit it as-is in its own
  commit, never squash it into a feature change.
- Windows-only failure: check the `pwsh` shell block and
  `fileformats` handling in `options.lua` before touching the plugin.
- SSH clipboard failure: check the OSC52 block, not the plugin.

## Do / Do not

Do: fix at plugin-spec level, reuse LazyVim extras, keep `desc` on
every key, verify headless, keep the diff reviewable in one screen
when possible.
Do not: hand-edit `lazy-lock.json`, rewrite `init.lua` / `lazy.lua`
bootstrap, change global `lazy` / `version` defaults, convert `opts`
to `config` without reason, steal another plugin's `<leader>` prefix,
add `CLAUDE.md` or other pointer files.
